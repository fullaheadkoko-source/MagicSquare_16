# PRD — MagicSquare (4x4, two missing numbers)

작성일: 2026-04-27  
프로젝트명: **MagicSquare**  
도메인: **4x4 Magic Square completion (two missing numbers)**  
주 언어: **Python 3.10+**  

---

## 1. 제품 개요

### 1.1 문제 정의(요약)
- 본 제품은 \(4 \times 4\) 격자에서 **합의된 값 집합과 규칙**(불변식)을 만족하는 **완성된 배치**를 산출하거나, 그러한 배치의 **존재 여부를 판정**하는 문제를 다룬다.
- “마방진을 만든다”가 아니라, **입력/출력 계약**과 **검증 가능한 불변식**을 먼저 고정하고, 이를 **TDD**로 보호하는 학습용 시스템이다.

### 1.2 목적(학습 목적)
- **Invariant 중심 설계 사고** 훈련(“항상 참이어야 하는 것”을 규칙으로 고정)
- **Dual-Track TDD** 훈련(UI 계약 테스트와 Domain 규칙 테스트를 병렬로 RED→GREEN→REFACTOR)
- **입력/출력 계약 명확화** 훈련(검증 가능하고 회귀 방지되는 스펙)
- **Clean Architecture(ECB)** 레이어 분리 훈련(의존성 방향 준수)

## 4. 스코프(기능 요구사항)

### 4.1 입력 계약(Input schema) — 고정
- 입력은 **정수 4x4 행렬**이다.
- 셀 값은 **0 또는 1..16**만 허용한다.
- **0은 빈칸**을 의미한다.
- **0은 정확히 2개**여야 한다.
- **0을 제외한 값은 중복이 없어야 한다.**

### 4.2 출력 계약(Output schema) — 고정(성공 시)
- 성공 결과는 **길이 6의 정수 배열**이다.
- 포맷: `[r1, c1, n1, r2, c2, n2]`
  - `r1,c1,r2,c2`: **1-index 좌표**(1..4)
  - `n1,n2`: 입력에서 누락된 두 숫자
- 빈칸 좌표 순서:
  - **행 우선(row-major), 열 증가**로 스캔하여 발견된 0의 좌표를 `(firstEmpty, secondEmpty)`로 고정한다.
- `n1,n2` 순서 규칙(결정적 출력 정책):
  - **기본 배정**: `firstEmpty=smallMissing`, `secondEmpty=largeMissing`
  - 기본 배정이 마방진이면 그 순서로 반환
  - 기본 배정이 마방진이 아니고, **반대 배정**이 마방진이면 반대 순서로 반환
  - 둘 다 아니면 실패(해 없음)

### 4.3 에러 계약(Error schema) — 고정(실패 시)
- 실패 결과는 `error` 객체로 반환한다.
  - `code`: 표준 코드(아래 중 하나)
  - `message`: 표준 문구(아래 문자열과 **완전 일치**)
  - `details`: 선택(테스트 가능한 고정 필드만 허용)

#### 표준 에러 코드/문구(정확히 일치)
| code | message (정확히 일치) | 발생 조건 |
|---|---|---|
| `UI_INVALID_SHAPE` | `Matrix must be 4x4.` | 입력이 4x4가 아님 |
| `UI_INVALID_EMPTY_COUNT` | `Matrix must contain exactly 2 empty cells (0).` | 0의 개수가 2개가 아님 |
| `UI_OUT_OF_RANGE` | `Cell values must be 0 or 1..16.` | 값이 0 또는 1..16 범위를 벗어남 |
| `UI_DUPLICATE_NON_ZERO` | `Non-zero values must be unique.` | 0을 제외한 중복 존재 |
| `UI_UNSOLVABLE` | `No magic square completion exists for this input.` | 두 배정 모두 마방진 실패 |
| `UI_DATA_ERROR` | `Failed to persist or load the matrix.` | (선택) 저장/로드 실패 |

#### 에러 반환 규칙(회귀 보호)
- 실패 시 **첫 위반 1개만** 반환한다(에러 리스트 금지).
- 에러 우선순위는 아래 순서를 고정한다.
  - **Shape → EmptyCount → Range → Duplicate → MissingNotTwo → Unsolvable → Data**

## 5. 도메인 불변식(Invariants)

### 5.1 입력 계약 불변식(Preconditions)
- **I-01 (Shape)**: 입력은 정확히 4x4
- **I-02 (EmptyCount)**: 0은 정확히 2개
- **I-03 (Range)**: 각 값은 0 또는 1..16
- **I-04 (UniqNonZero)**: 0 제외 중복 없음
- **I-05 (MissingExactly2)**: 1..16 중 누락 값은 정확히 2개

### 5.2 마방진 규칙 불변식(Domain Rules)
- **I-06 (MagicConstant)**: 값 집합이 1..16인 완성 상태에서 마방진 상수는 **34**
  - 근거: \( \sum_{k=1}^{16} k = 136 \), \(136/4 = 34\)
- **I-07 (RowSum)**: 모든 행 합 동일(완성 상태에서는 34)
- **I-08 (ColSum)**: 모든 열 합 동일(완성 상태에서는 34)
- **I-09 (DiagSum)**: 두 대각선 합 동일(완성 상태에서는 34)
- **I-10 (DeterministicOrderRule)**: 4.2의 `n1,n2` 출력 순서 규칙은 항상 결정적이어야 함

## 6. 비기능 요구사항(NFR)

### 6.1 결정성(Determinism)
- 동일 입력은 항상 동일 출력(좌표 및 `n1,n2` 순서 포함)을 반환해야 한다.

### 6.2 테스트/품질 목표
- 최소 커버리지: **80% 이상**
- 목표(학습용 지표):
  - **Domain Logic 95%+**
  - **UI Boundary 85%+**
  - **Data 80%+**

### 6.3 변경 금지(회귀 보호) 항목
- 입력 계약(4x4, 0=2개, 범위, 중복 금지) 변경 금지
- 출력 포맷(`int[6]`, 1-index, `[r1,c1,n1,r2,c2,n2]`) 변경 금지
- 에러 메시지 문자열 변경 금지(문자 1개 변경도 회귀로 간주)
- 에러 우선순위 변경 금지

## 7. 아키텍처 요구사항(ECB)

### 7.1 레이어 정의
- **boundary**: 외부 입출력(입력 파싱/스키마 검증, 출력 포맷팅, 에러 매핑)
- **control**: 유스케이스 오케스트레이션(흐름 제어, entity 조합, 결과/실패 구성)
- **entity**: 도메인 데이터/규칙(불변식 보존, 순수·결정적 로직)

### 7.2 의존성 방향
- 허용: boundary → control → entity
- 금지: entity → control/boundary, control → boundary

## 8. 사용자 스토리(요약) 및 승인 기준(AC)

### 8.1 Story 1 — 입력 검증
- **AC**
  - 4x4가 아니면 실패
  - 빈칸(0) 2개가 아니면 실패
  - 0 제외 중복이 있으면 실패
  - 값 범위(0 또는 1..16) 위반 시 실패

### 8.2 Story 2 — 빈칸 탐색
- **AC**
  - row-major 순서 유지
  - 정확히 2개 좌표 반환

### 8.3 Story 3 — 누락 숫자 탐색
- **AC**
  - 1..16 중 누락 2개
  - 오름차순(small, large)으로 반환

### 8.4 Story 4 — 마방진 판정
- **AC**
  - 모든 행 합 동일
  - 모든 열 합 동일
  - 두 대각선 합 동일

### 8.5 Story 5 — 두 조합 시도(완성/출력)
- **AC**
  - small→firstEmpty / large→secondEmpty 먼저 시도
  - 실패 시 reverse 시도
  - 성공 시 길이 6 배열로 반환(좌표 1-index)
  - 둘 다 실패 시 `UI_UNSOLVABLE`

## 10. 가정 / 리스크

### 10.1 가정(Assumptions)
- 값 집합은 **1..16**이며, 빈칸은 **정확히 2개(0)** 이다.
- 해결 전략은 “두 빈칸에 두 숫자 배정”의 **2가지 조합 시도**로 충분하다(본 스코프).

### 10.2 리스크(Risks)
- 스펙의 핵심(에러 문구, 출력 포맷)이 변경되면 테스트가 대규모로 깨질 수 있다(의도된 회귀 보호).
- 입력 계약 위반 처리에서 “우선순위”가 흔들리면 외부 계약이 불안정해진다(반드시 테스트로 고정).
