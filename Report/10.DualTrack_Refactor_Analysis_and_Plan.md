## 목적

본 문서는 MagicSquare(4×4) 프로젝트에서 지금까지 진행한 **Dual-Track(UI+Logic) 관점 분석 결과**(테스트 현황, Code Smell, ECB/SRP 점검)와 **리팩토링 계획**을 `Report/`로 이관한 것입니다.  
코드 변경은 포함하지 않습니다.

---

## 0) 기준선 확인 (Step 0)

- **실행 명령**: `python -m pytest`
- **결과 요약**: **FAIL** — 총 15개 수집, **12 failed / 3 passed**
  - `tests/test_logic_red.py`: `pytest.fail("RED: ...")`로 고정된 RED 테스트 다수 실행됨
  - `tests/test_ui_boundary_red.py`: `pytest.fail("RED: ...")`로 고정된 RED 테스트 다수 실행됨

### 시사점

- “먼저 테스트 실행 → 리팩토링 → 테스트 재실행(항상 GREEN 유지)” 규칙을 적용하려면, 현재 상태에서는 **GREEN 기준선이 충족되지 않음**.
- `pytest.fail(...)` 기반의 RED 테스트를 통과시키려면, 리팩토링만으로는 불가능하며 **기능 구현/검증 로직 추가(GREEN 단계)**가 선행되어야 함.

## 4) ECB(Entity-Control-Boundary) 관점 분석

### 4-1. 각 파일의 현재 ECB 역할

- **`magicsquare/domain.py` → Control(규칙/계산) 성격**
  - 상태를 보관하는 Entity가 아니라, 입력을 받아 계산하는 순수 함수 중심
- **`magicsquare/boundary.py` → Boundary 역할은 “부분적”**
  - shape(4×4) 검증은 경계 역할에 적합
  - 그러나 빈칸 2개/범위/중복 등 계약 검증과 에러 스키마는 UI로 일부 유출
- **`magicsquare/screen/app.py` → Boundary(UI) + Control 성격이 혼재**
  - UI 이벤트 핸들러에서 입력 정규화, 계약 검증, 도메인 전제 판단을 직접 수행

### 4-2. 잘못된 위치의 코드(이동 권장)

- `magicsquare/screen/app.py`의 “계약 검증(빈칸2개/범위/중복/우선순위)”은 **`magicsquare/boundary.py`**로 집중하는 것이 ECB에 부합
- `magicsquare/screen/app.py`의 “좌표/결과 포맷 조립”은
  - 단순하면 UI에 남길 수 있으나,
  - 커지면 Control(UseCase/Formatter)로 추출해 UI를 “입력 수집/표시”로 축소하는 것이 안정적

### 4-3. domain.py 내 Entity/Control 혼재 여부 및 분리 포인트

- 현 시점 `domain.py`는 Entity보다 Control에 가까워 “혼재”는 크지 않음
- 다만 보드 불변식(4×4, 빈칸 2개, 범위, 중복)을 데이터 모델이 책임지게 할 경우:
  - Entity 후보: `Board`/`Matrix4x4`/`Cell` 등 값 객체
  - Control 후보: `Solver`/`UseCase`/`CompletionPolicy`

### 6-2. 테스트 선행 필요 항목

- `magicsquare.boundary` (현재 RED로 남은 계약)
  - 빈칸(0) 정확히 2개 검증 + `UI_INVALID_EMPTY_COUNT`
  - 값 범위 검증 + `UI_OUT_OF_RANGE`
  - 0 제외 중복 검증 + `UI_DUPLICATE_NON_ZERO`
- `magicsquare.domain` (현재 RED로 남은 규칙/해결)
  - `is_magic_square` 관련 케이스
  - `solution`/완성 정책 관련 케이스(길이 6, 1-index, 조합 시도 규칙)

### 6-3. 리팩토링 후 검증 방법

- **회귀 테스트 실행 명령어**
  - `python -m pytest`
- **외부 동작(기능) 불변 확인**
  - 표준 에러 `code/message` 완전 일치 + 우선순위 규칙을 테스트로 고정

  - GUI 스모크(수동): `python -m magicsquare` 실행 후 기본 입력/오류 입력에서 결과/경고가 스펙과 일치하는지 확인
