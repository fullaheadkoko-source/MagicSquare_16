## 2. Dual-Track RED 구조

```
UI RED (Boundary)     Logic RED (Domain)
        ↓                      ↓
              둘 다 실패 상태(RED)
```

- **UI RED**: `4×4 int[][]`, `0` 2개, `1~16`, 중복 금지, 출력 `int[6]`·**1-index** 좌표 등 **공개 계약** 검증.
- **Logic RED**: `find_blank_coords`, `find_not_exist_nums`, `is_magic_square`, `solution` 등 **단위 불변식** 검증.

## 3. 문제 정의(입력·출력·상수)

| 항목 | 규칙 |
|:---|:---|
| 입력 | `4×4` `int[][]`, `0` = 빈칸 **정확히 2개**, 나머지 `1~16`, `0` 제외 중복 없음 |
| 출력 | `int[6]` — `[r1, c1, n1, r2, c2, n2]`, 좌표 **1-index** |
| 마방진 상수 | 4×4 완성 시 행·열·대각선 합 **34** |

## 4. Track A — UI / Boundary RED (설계 요약)

구현 없이 `pytest` 등으로 작성할 때 **ImportError / 예외 미발생 / 길이·좌표 불일치**로 RED가 된다.

| Test ID | 시나리오 | 보호 Invariant / 계약 |
|:---|:---|:---|
| **UI-RED-01** | 3×4, 4×3, 가변 행 길이, 빈 리스트 | **I-01 Shape**: 정확히 4×4 |
| **UI-RED-02** | `0` 개수 0, 1, ≥3 | **I-02 EmptyCount**: 빈칸 정확히 2개 (`UI_INVALID_EMPTY_COUNT` 등 PRD 정렬) |
| **UI-RED-03** | `1~16` 밖 값, 잘못된 셀 값 | **I-03 Range**: 비빈칸 ∈ [1,16] |
| **UI-RED-04** | `0` 제외 중복 숫자 | **I-04 UniqNonZero** |
| **UI-RED-05** | 유효 퍼즐로 `solution` 호출 | 성공 시 **반환 길이 6** |
| **UI-RED-06** | 유효 퍼즐로 `solution` 호출 | **좌표 1-index** (1~4) |

### 4.1 Given / When / Then (요약)

- **UI-RED-01** — *Given*: 비정형 행렬 — *When*: 검증 또는 `solution` — *Then*: 예외 또는 PRD 오류 코드·메시지.
- **UI-RED-02** — *Given*: `0` ≠ 2인 4×4 — *When*: 동일 — *Then*: `UI_INVALID_EMPTY_COUNT` 및 표준 `message`.
- **UI-RED-03** — *Given*: 범위 위반 1칸 이상 — *When*: 동일 — *Then*: 범위 위반 오류.
- **UI-RED-04** — *Given*: 중복 비영 — *When*: 동일 — *Then*: 중복 오류.
- **UI-RED-05** — *Given*: 계약 만족 퍼즐 — *When*: `solution` — *Then*: `len(result) == 6`.
- **UI-RED-06** — *Given*: 동일 — *When*: `solution` — *Then*: `1 <= r*,c* <= 4` 및 기대 해와 일치 시 좌표 검증.

`Report/07`의 TC-MS-A-002~004 등과 **교차 매핑** 가능.

## 5. Track B — Logic RED (설계 요약)

| Test ID | 대상 | 시나리오 | 보호 Invariant |
|:---|:---|:---|:---|
| **LOG-RED-01** | `find_blank_coords` | 표준 2-zero 보드 | row-major 순서, 좌표 **2개** (내부 0/1-index 팀 규약 고정) |
| **LOG-RED-02** | `find_not_exist_nums` | 동일 보드 | 누락 **2개**, **오름차순** |
| **LOG-RED-03** | `is_magic_square` | 완성 마방진 | 행·열·대각 **34** |
| **LOG-RED-04** | `is_magic_square` | 합 깨진 보드 | `False` |
| **LOG-RED-05** | `is_magic_square` | `0` 포함 미완성 | `False` (정책 고정) |
| **LOG-RED-06** | `solution` | 유효 입력 | `int[6]`, 1-index |
| **LOG-RED-07** | `solution` + 판정 | 채운 보드 | `is_magic_square` → `True` |
| **LOG-RED-08** | `solution` | 고정 예제 | **I-10**: 작은 수 → 첫 빈칸 우선 시도 |
| **LOG-RED-09** | `solution` | 역순 보정 케이스 | 기본 실패 시 **reverse** 시도 계약 |

**RED 명시**: 모듈·함수 미존재 또는 스텁은 테스트가 깨지는 상태여야 하며, GREEN 이전에는 통과시키지 않는다.

`Report/02`의 UC-01~04, I-06~I-10 및 `Report/07` TC-MS-A-001 등과 정렬.

## 7. 다음 단계(본 보고서 범위 밖)

- **GREEN**: 최소 구현으로 위 테스트를 **하나씩** 통과.
- **REFACTOR**: 중복 제거·이름 정리 — 본 문서에서는 수행하지 않음.
- **Git**: RED 테스트 커밋을 `test:` 또는 팀 규칙에 맞는 접두사로 분리 커밋 권장.
